# v0.8.3 — 适配 DSH `>= 0.2.2-rc.2` 宿主接口变更

> 发布日期：2026-11-17
> 上一版本：[v0.8.2](./v0.8.2.md)
> 关联 Issue：[#2](https://github.com/SShiRkiT/dsh-orchestrator/issues/2)

## 修复内容

- **适配扁平派发参数**：`delegate` / `orchestrate` 将 `cwd`、`prompt`、`parent`、`agentOptions`、`maxDepth` 与 `outputSchema` 直接传入 `startActivation(spec)` 顶层，修复旧 `spec.request.*` 形状导致的派发失败。省略 `name`，由宿主分配名称；`delegate` 返回值仍为 `{ kind: 'activation', subagentId, writeScope: { leaseId, scope } }`，不受阶段 `outputSchema` 影响。
- **恢复自动重试投递**：改用公开方法 `ctx.subagents.prompt()`，请求仅包含 `requestId`、`childSessionId`、`delivery: 'queue'` 与 `content`，从收据读取 `messageId`。不再依赖已移除的私有 `deliverPrompt` 入口。
- **补全工具目录**：使用 `ctx.agents.list()`，按运行期与持久化委派深度排除子代理，汇总全局和根代理 scope 中可枚举的工具。单个 scope 读取失败不影响其他 scope；代理列表不可读时仍保留可读的全局目录。
- **保留默认权限策略**：`allowedTools` 默认集合与 v0.8.2 一致，仍为 12 项且不包含 `wait_agent`。宿主已注册并发布该工具目录时，面板可以列出未勾选的 `wait_agent`；用户可手动勾选放行。调度模式开启且使用默认配置时，主代理工具列表隐藏该工具，执行门禁拒绝调用。

## 升级说明

**本版本含破坏性变更：最低宿主要求提升至 DSH `>= 0.2.2-rc.2`，不再兼容 `0.2.2-rc.1` 及更早版本。**

| 宿主版本 | 升级建议 |
| --- | --- |
| DSH `>= 0.2.2-rc.2` | 升级到 v0.8.3 |
| DSH `<= 0.2.2-rc.1` | 保持 v0.8.2，或先升级宿主 |

重新安装插件时，先移除旧条目，避免重复注册，再添加本仓库并完全退出、重新打开 DSH。配置项无增删；已有自定义 `allowedTools` 的用户应按自己的配置核对权限。

**重试来源变化**：公开 prompt 通道将子代理重试提示记为 `source.kind = 'user'`，不再携带专属 `'orchestrator-retry'` 标记；成功接受的消息通过 `source.rpcId` 记录该次 `requestId`。排查时需结合提示正文、目标子代理与时间定位，收据只表示消息已被接受，不表示任务完成。发给父代理的重试失败或预算耗尽通知仍保留 `'orchestrator-retry'` 来源。

**回滚**：在 DSH `0.2.2-rc.2+` 上降级到 v0.8.2 会重新出现派发失败；如需回退，应同时回退到兼容的旧宿主。
