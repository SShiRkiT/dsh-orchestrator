# v0.8.2 — 调度模式切换延迟状态通知

> 发布日期：2026-11-16
> 上一版本：[v0.8.1](https://github.com/SShiRkiT/dsh-orchestrator/releases/tag/v0.8.1)

## 这个版本解决什么问题

在 v0.8.1 修复关闭态的工具面与门禁之后，已有长会话在**中途切换「调度模式」开关**时仍存在上下文惯性问题：

- 面板点击开关只更新运行期配置，主代理自身在历史对话中并不知道状态已经变更，仍可能沿用前一轮的规划/委派惯性（或误以为常规工具仍被禁用）
- 若在开关点击的瞬间立即调用 `inject` / `steer` 向会话推送消息，会把提示语直接插进用户仍在阅读或尚未发起新请求的回合里，产生多余气泡或打断风险

本版本引入**基于 `agent/pre-step` 的延迟切换通知机制**：开关变化时仅做状态记录，等用户发起下一轮真实对话步骤时再随该步骤附带一条状态变更提示，做到**零额外气泡、零多余轮次、多轮切换自动防抖合并**。

## 变更内容

### 1. 延迟切换状态追踪与防抖合并

新增 `lib/switch-notice.js`，导出 `SWITCH_SOURCE_KIND`（`'orchestrator-switch'`）、`switchNoticeText(enabled)` 与 `createSwitchNotices({ readEnabled, logger })`：

- **基线建立**：主代理创建（`agent/created`）时以当前 `isDispatchEnabled(config)` 作为基线，新创建的空白会话不会继承历史切换提示
- **变更记录**：`loader/volatile-update` 触发时仅记录每个存活主代理的最新开关状态，不立即发送任何消息
- **往返归零与多次合并**：下一轮前若连续切换多次（如 `on -> off -> on`），回到原基线则自动消除待发通知；最终落在不同状态时，仅保留 1 条描述最终状态的通知
- **明确工具变更文案**：
  - 开启时告知主代理恢复只做规划并通过 `delegate` / `orchestrate` 委派子代理，常规工具已被拦截
  - 关闭时告知主代理可直接使用 `read` / `write` / `edit` / `bash` / `glob` / `grep` 等常规工具执行任务，不要再调用 `delegate` 或 `orchestrate`

### 2. 通过 `agent/pre-step` 无感随轮注入

在 `lib/index.js` 中新增并导出 `createSwitchPreStep({ switchNotices, loadLlm, logger })`，同时抽取共享的 `createUserMessageLoader` 供巡检与切换通知复用：

- 全局订阅宿主 `agent/pre-step` 瀑布流钩子（`{ global: true }`），在宿主 `inbox.claim` 之后、写入本步消息事件之前追加通知消息（携带 `source.kind = 'orchestrator-switch'`）
- **安全边界保护**：
  - 仅作用于主代理，委派子代理（`isDelegatedChild(agent)`）永不接收切换通知
  - 若外层钩子拒绝（`decision.kind === 'reject'`）、步骤被中止（`payload.signal.aborted`）、或空消息步骤（`messages.length === 0`），保留待发状态不消耗
  - 先解析 `@deepseek-ai/dsh-llm` 的 `createUserMessage` 再消费待发通知，防止动态导入失败或中途 abort 导致通知丢失
  - `agent/disposed` 时清理该代理基线与待发记录，避免同 ID 重建时继承旧状态
