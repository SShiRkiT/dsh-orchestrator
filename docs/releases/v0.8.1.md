> 发布日期：2026-11-16
> 上一版本：[v0.8.0](https://github.com/SShiRkiT/dsh-orchestrator/releases/tag/v0.8.0)
> 提交范围：`7e0ebca..efd4039`

## 这个版本解决什么问题

在 v0.8.0 及更早版本中，**关闭「调度模式」开关后，主代理仍然按「只负责规划、必须委派子代理」的规则运行**。

具体表现为：

- 主代理继续主动调用 `delegate` / `orchestrate`，而不是自己执行任务
- 部分模型（如 GPT 系列）会口头声称「我无权调用本地工具」，即使 `read` / `edit` / `bash` 实际已可用
- 用户明确关闭编排后，主代理无法恢复正常自主执行

根因是**声明层与执行层脱节**：关闭开关只放行了执行门禁，但没有从模型可见的工具面和工具描述中撤除强制委派指令。

## 修复内容

### 1. 关闭态从工具面移除派发工具

关闭调度模式时，`delegate` 与 `orchestrate` 不再出现在主代理的工具列表中，常规工具（`read` / `write` / `edit` / `bash` / `glob` / `grep` 等）恢复可见。

涉及：`lib/tool-surface.js`

### 2. 关闭态剥离强制委派规则文本

`delegate` 与 `orchestrate` 的工具描述在关闭态不再注入 `mainAgentRule`，即不再向模型下发：

> 主代理规则：主代理只负责规划。一切读/写/编辑/搜索/命令/抓取/检查都只在子代理中通过 delegate 或 orchestrate 执行；主代理绝不自己调用……

描述改为只保留工具本身的功能说明。

涉及：`lib/delegate.js`、`lib/orchestrate.js`、`lib/rules.js`

### 3. 执行门禁兜底拦截

关闭态下，门禁放行所有常规工具，但**仍拦截** `delegate` / `orchestrate`。这层兜底用于挡住两类调用：

- 模型凭历史对话惯性产生的幻觉调用
- `run_code` 内嵌的 `tools.delegate` / `tools.orchestrate` 调用

拒绝文案统一为：

```
orchestrator: "<tool>" is disabled while dispatch mode is off.
Execute the task directly with your regular tools instead of delegating.
```

涉及：`lib/gate.js`、`lib/api.js`

### 4. 统一开关读取入口

新增 `isDispatchEnabled(config)`，作为插件内**唯一**的开关读取函数：

- 兼容 schemastery volatile 引用（`.get()`）与普通布尔值
- 只有显式 `false` 才算关闭；缺失、`undefined` 或读取异常一律视为开启
- 工具面、工具描述、执行门禁三处消费方全部通过它读取，避免逻辑漂移

涉及：`lib/worker.js`

## 行为对照

| 状态 | `read` / `write` / `bash` 等常规工具 | `delegate` / `orchestrate` |
| --- | --- | --- |
| **开启调度模式** | 从工具面移除，调用被拒绝 | 工具面可见，正常放行 |
| **关闭调度模式** | 工具面可见，正常放行 | 从工具面移除，调用被拒绝 |

## 升级说明

本版本为**缺陷修复**，无破坏性变更，无配置项增删。直接升级即可。

若你此前通过面板关闭过调度模式但行为未生效，升级后请重启客户端一次，确保插件实例加载新代码。
